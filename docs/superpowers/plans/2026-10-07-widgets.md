# Configurable Widgets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking. Execute independently in this session as the user requested.

**Goal:** Ship configurable table/Today/count widgets and draft-first Quick add while preserving locked-screen privacy and correct calendar semantics.

**Architecture:** One core compiler produces eager or transferable plans. The host publishes coherent read-only SQLite generations; a lightweight extension rebinds calendar slots at runtime and uses existing guarded host navigation for actions.

**Tech Stack:** TypeScript/Bun, generated DTOs, Foundation/GRDB, WidgetKit/App Intents, SwiftUI/XcodeGen, existing Ad Hoc CI.

**Spec:** [Approved widget design](../specs/2026-10-07-widgets-design.md).

## Global Constraints

- Table/saved-view list, Today, Count and Quick add only; no pinned-record widget or Live Activity.
- iOS 17 baseline; controls require iOS 18; later APIs individually gated.
- No JSC, writer, credential, network sync, or second view compiler in the reader.
- List limit 20; bounded count probe 10,001 with `10,000+` display above 10,000.
- Locked accessories expose counts/generic labels only; capture never writes before Save.
- Generic runtime IDs only; daily tasks above configured Notes remains separate acceptance.

## Review Focus

- A literal equal to Today must remain literal after rollover (Task 1).
- A partly written publication must never pair old SQL with new rows (Task 2).
- Repeated intent execution must retain one draft and leave an existing editor untouched (Task 4).
- Revoked widget access must not retain sensitive stale content (Tasks 2, 3).
- Large text and redaction must affect accessibility labels as well as visible text (Task 3).
